## 1. Цель работы

Целью работы было изучить базовые методы обработки текстовых данных и применить их для задачи бинарной классификации тональности твитов.

В рамках работы решалась задача определения эмоциональной окраски текста:

- `positive` — положительный твит;
- `negative` — отрицательный твит.

Для решения задачи использовались методы векторизации текста и алгоритмы машинного обучения. Основное внимание было уделено сравнению разных способов извлечения признаков из текста и сравнению качества нескольких моделей классификации.

## 2. Подготовка данных

Изначально были загружены два набора данных:

```python
positive = pd.read_csv('positive.csv', sep=';', usecols=[3], names=['text'])
positive['label'] = ['positive'] * len(positive)

negative = pd.read_csv('negative.csv', sep=';', usecols=[3], names=['text'])
negative['label'] = ['negative'] * len(negative)

df = pd.concat([positive, negative])
````

Файл `positive.csv` содержит положительные твиты, а файл `negative.csv` — отрицательные.
Из каждого файла была взята колонка с текстом твита. После этого для каждого текста была добавлена метка класса:

* `positive` для положительных твитов;
* `negative` для отрицательных твитов.

Затем оба набора были объединены в один датафрейм `df`.

Итоговая структура данных:

| text        | label               |
| ----------- | ------------------- |
| текст твита | positive / negative |

## 3. Разделение выборки

Для обучения и проверки моделей датасет был разделён на обучающую и тестовую выборки:

```python
x_train, x_test, y_train, y_test = train_test_split(df.text, df.label)
```

Где:

* `x_train` — тексты для обучения модели;
* `x_test` — тексты для проверки модели;
* `y_train` — правильные ответы для обучающих текстов;
* `y_test` — правильные ответы для тестовых текстов.

Такой подход позволяет проверить, насколько хорошо модель работает на новых данных, которые она не видела во время обучения.

## 4. Базовая модель: CountVectorizer + LogisticRegression

В качестве базового варианта была использована модель `LogisticRegression` и векторизация текста с помощью `CountVectorizer`.

```python
vectorizer = CountVectorizer(ngram_range=(1, 1))

vectorized_x_train = vectorizer.fit_transform(x_train)

clf = LogisticRegression(random_state=42, max_iter=1000)
clf.fit(vectorized_x_train, y_train)

vectorized_x_test = vectorizer.transform(x_test)

pred = clf.predict(vectorized_x_test)

print(classification_report(y_test, pred))
```

В данном случае использовались **униграммы слов**, то есть отдельные слова как признаки.

Например, текст:

```text
хороший фильм
```

превращается в признаки:

```text
хороший
фильм
```

`CountVectorizer` считает, сколько раз каждое слово встретилось в тексте.

## 11. TF-IDF-векторизация

Далее была проведена серия экспериментов с `TfidfVectorizer`.

В отличие от `CountVectorizer`, который считает только количество слов, `TfidfVectorizer` учитывает важность слова.

Слова, которые часто встречаются почти во всех текстах, получают меньший вес. Более редкие и информативные слова получают больший вес.

Были проверены следующие варианты:

* униграммы;
* биграммы;
* триграммы;
* пентаграммы.

---

## 18. Почему длинные n-граммы ухудшили результат

Униграммы позволяют модели находить общие признаки тональности:

```text
хороший
плохой
ужасный
отличный
люблю
ненавижу
```

Такие признаки встречаются часто и помогают модели делать устойчивые выводы.

Биграммы уже более специфичны:

```text
очень хорошо
не понравилось
плохой фильм
```

Они могут быть полезны, но встречаются реже.

Триграммы и пентаграммы ещё более специфичны:

```text
мне очень понравился
это было очень плохо
мне совсем не понравился этот
```

Чем длиннее n-грамма, тем меньше вероятность, что точно такая же последовательность встретится и в обучающей, и в тестовой выборке.

Поэтому модель начинает хуже работать на новых данных.

## 23. Польза символьных n-грамм

Несмотря на то, что в данном датасете символьные признаки дают завышенное качество из-за смайликов, в целом это полезный подход.

Символьные n-граммы часто применяются в задачах:

* определения языка текста;
* обработки текстов с опечатками;
* анализа коротких сообщений;
* обработки языков без хороших готовых токенизаторов;
* классификации текстов со сленгом и нестандартным написанием.

Преимущество символьных признаков в том, что для них не нужны:

* токенизация;
* лемматизация;
* морфологический анализатор;
* словарь языка.

## 25. Итоговые выводы

В ходе работы была решена задача бинарной классификации тональности твитов.

Были изучены и применены разные способы представления текста в виде числовых признаков:

* `CountVectorizer`;
* `TfidfVectorizer`;
* словесные униграммы;
* биграммы;
* триграммы;
* пентаграммы;
* символьные признаки;
* токенизация через `word_tokenize`.

Также были обучены и сравнены несколько моделей классификации:

* `LogisticRegression`;
* `XGBClassifier`;
* `LinearSVC`.

Лучший честный результат среди основных моделей показала логистическая регрессия с улучшенной токенизацией и удалением шумовых слов:

```text
accuracy = 0.78
weighted avg f1-score = 0.78
```

Базовая `LogisticRegression` с `CountVectorizer` также показала хороший результат:

```text
accuracy = 0.76
weighted avg f1-score = 0.76
```

Среди альтернативных моделей лучший результат показала `LinearSVC`:

```text
accuracy = 0.75
weighted avg f1-score = 0.75
```

`XGBClassifier` оказался хуже:

```text
accuracy = 0.72
weighted avg f1-score = 0.72
```

В экспериментах с TF-IDF лучше всего сработали униграммы. При увеличении длины n-грамм качество снижалось. Особенно плохой результат получился на пентаграммах, потому что длинные последовательности слов редко повторяются в обучающей и тестовой выборках.

Также было обнаружено, что пунктуация и смайлики являются очень сильными признаками для данного датасета. Если их не удалять, модель может получить почти идеальное качество, но такой результат не всегда означает настоящее понимание текста. Скорее всего, модель использует простые подсказки вроде:

```text
:)  → positive
:(  → negative
```

Поэтому при оценке качества модели важно учитывать не только численные метрики, но и то, за счёт каких признаков модель достигает результата.

## 26. Заключение

Работа показала, что для задач классификации текстов простые линейные модели могут быть очень эффективными. `LogisticRegression` оказалась сильным базовым решением и показала лучшее качество среди основных моделей.

Также было показано, что качество классификации сильно зависит от способа векторизации текста. Униграммы оказались более устойчивыми, чем длинные n-граммы, а символьные признаки дали очень высокий результат из-за наличия в данных смайликов и пунктуации.

Главный вывод: при работе с текстовыми данными важно не только обучить модель, но и внимательно анализировать признаки, потому что иногда высокая точность может быть вызвана не качественным пониманием текста, а наличием в данных сильных искусственных подсказок.
