### 7. Создание новых признаков

На следующем этапе был создан новый признак `average_score`. Он показывает средний балл студента по трём предметам: математике, чтению и письму.

Формула расчёта:

```text
average_score = (math_score + reading_score + writing_score) / 3
```

Создание такого признака позволило оценивать общую успеваемость студента не по одному предмету, а сразу по совокупности трёх результатов.

Также был создан дополнительный признак `passed`, который показывает, можно ли условно считать студента успешно сдавшим. Если средний балл студента был не ниже 60, значение признака принимало значение `yes`, иначе — `no`.

### 12. Настройка CI/CD pipeline

В репозитории был настроен CI/CD pipeline с использованием файла `.sourcecraft/ci.yaml`.

Pipeline выполняет следующие действия:

1. запускается автоматически при push или pull request;
2. использует Docker-образ `python:3.11`;
3. устанавливает зависимости из файла `requirements.txt`;
4. устанавливает дополнительные инструменты для работы с Jupyter Notebook;
5. добавляет в notebook специальную ячейку, подтверждающую выполнение кода именно в CI-раннере;
6. выполняет notebook с помощью `jupyter nbconvert --execute`;
7. сохраняет выполненный notebook под именем `executed_lab.ipynb`;
8. генерирует HTML-отчёт `report.html`;
9. сохраняет `executed_lab.ipynb` и `report.html` как артефакты pipeline.

Особенностью CI является то, что в notebook автоматически добавляется ячейка с информацией о среде выполнения. Эта ячейка выводит текст о том, что notebook был выполнен в SourceCraft CI runner, а также показывает данные окружения: время выполнения, hostname, платформу, версию Python и текущую директорию. Это подтверждает, что код был выполнен не локально и не в Google Colaboratory, а именно в CI/CD окружении.

### 14. Возникшие трудности

В процессе выполнения лабораторной работы возникла трудность с интерпретацией значения `none` в столбце `test_prep`.

Также важно было правильно оформить графики: добавить заголовки, подписи осей и краткие выводы под каждым графиком. Это необходимо для того, чтобы notebook можно было понять без дополнительных устных пояснений.

Ещё одной задачей была настройка CI/CD pipeline. Нужно было сделать так, чтобы notebook не просто лежал в репозитории, а автоматически выполнялся в раннере, после чего создавался HTML-отчёт и сохранялся как артефакт.
