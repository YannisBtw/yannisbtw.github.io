## 📌 Описание проекта

В данном проекте решается задача бинарной классификации — прогнозирование вероятности дефолта клиента (просрочки платежа) на основе его финансовых характеристик.

Целевая переменная:

* **SeriousDlqin2yrs** — наличие серьёзной просрочки (1 — да, 0 — нет)

---

## 🎯 Цель работы

* Исследовать различные алгоритмы классификации
* Построить модель с наилучшим качеством (метрика ROC-AUC)
* Проанализировать влияние признаков и preprocessing
* Оценить возможность достижения ROC-AUC ≥ 0.9

---

## 📁 Данные

Датасет содержит информацию о клиентах:

* доход (MonthlyIncome)
* долговая нагрузка (DebtRatio)
* возраст (age)
* количество кредитов
* количество просрочек (30–59, 60–89, 90+ дней)
* количество иждивенцев

Особенности данных:

* сильный дисбаланс классов (~1:14)
* наличие выбросов
* пропущенные значения

---

## ⚙️ Предобработка данных

Были выполнены следующие шаги:

### 🔹 Обработка пропусков

* MonthlyIncome → заполнение медианой
* NumberOfDependents → заполнение нулём

### 🔹 Обработка выбросов

* Ограничение экстремальных значений (clip)
* Приведение признаков к адекватным диапазонам

### 🔹 Feature Engineering

Созданы новые признаки:

* бинарные признаки просрочек
* суммарные просрочки
* логарифмы (доход, долг)
* взаимодействия признаков
* нормализованные показатели (долг/доход и т.д.)

---

## 🤖 Использованные модели

Были протестированы следующие алгоритмы:

* Logistic Regression
* Random Forest
* LightGBM
* (опционально) kNN, SVM

---

## 📈 Результаты

| Модель              | ROC-AUC    |
| ------------------- | ---------- |
| Logistic Regression | ~0.66      |
| Random Forest       | ~0.84      |
| LightGBM            | ~0.85–0.86 |

---

## 🧠 Анализ результатов

* Простые модели (Logistic Regression) показали низкое качество
* Ансамблевые методы (Random Forest, Gradient Boosting) значительно лучше
* Наилучший результат показал **LightGBM**

📌 Вывод:

> Ансамблевые методы являются наиболее эффективными для задач классификации табличных данных.

---

## ⚠️ Ограничения модели

Дальнейшее улучшение качества затруднено из-за:

* малого числа признаков (~10)
* сильного дисбаланса классов
* перекрытия распределений классов
* наличия шума и выбросов

👉 Предполагаемый потолок качества: **ROC-AUC ≈ 0.86–0.89**
