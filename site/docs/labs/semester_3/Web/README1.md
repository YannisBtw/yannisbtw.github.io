title: ITMO Student Management

Frontend-приложение для управления данными студентов, разработанное на HTML, CSS и JavaScript в рамках лабораторной работы №1 по веб-программированию в ИТМО.

Для хранения данных на стороне клиента используется **IndexedDB**.

## Возможности

Приложение позволяет:

- просматривать список студентов в таблице;
- добавлять новых студентов;
- редактировать существующих студентов;
- удалять студентов;
- просматривать подробную информацию о студенте;
- валидировать вводимые пользователем данные;
- сохранять данные локально с помощью IndexedDB;
- работать с несколькими страницами приложения;
- использовать адаптивную верстку;
- разделять интерфейс, работу с данными и бизнес-логику.

## Данные студента

Для каждого студента хранятся следующие данные:

- `fullName` — ФИО;
- `group` — учебная группа;
- `isuId` — номер ИСУ;
- `dormitoryNumber` — номер общежития;
- `roomNumber` — номер комнаты;
- `moveInDate` — дата заселения;
- `isForeign` — является ли студент иностранным;
- `notes` — дополнительные заметки.

Кроме того, для каждого студента IndexedDB автоматически создает уникальный идентификатор `id`.

## Валидация

В приложении используется встроенная HTML-валидация совместно с дополнительной проверкой данных на JavaScript.

Основные правила валидации:

- ФИО должно содержать минимум 3 символа;
- группа должна состоять из одной заглавной латинской буквы и четырех цифр, например `P3120`;
- ИСУ ID должен быть шестизначным числом от `100000` до `999999`;
- номер общежития должен быть числом;
- номер комнаты должен быть числом;
- дата заселения должна быть раньше текущей даты.

Для дополнительной проверки используются методы Constraint Validation API:

```js
setCustomValidity()
reportValidity()
```

Это позволяет устанавливать собственные сообщения об ошибках и использовать стандартный механизм проверки HTML-форм.

### `index.html`

Главная страница приложения.

Содержит таблицу со списком студентов и элементы управления для:

- просмотра подробной информации;
- редактирования;
- удаления;
- перехода к добавлению нового студента.

### `student-form.html`

Страница формы добавления и редактирования студента.

Одна и та же форма используется для двух сценариев:

- создания новой записи;
- редактирования существующей записи.

При редактировании данные студента предварительно загружаются из IndexedDB и подставляются в соответствующие поля формы.

### `details.html`

Страница просмотра подробной информации о выбранном студенте.

Идентификатор студента передается через параметры URL, после чего соответствующая запись загружается из IndexedDB.


Таким образом, работа с базой данных вынесена отдельно от кода пользовательского интерфейса.

Отвечает за:

- получение списка студентов;
- отображение студентов в таблице;
- создание строк таблицы;
- обработку удаления студентов;
- переход к просмотру и редактированию записей.

### `js/form.js`

Отвечает за:

- обработку формы;
- валидацию данных;
- добавление нового студента;
- загрузку существующего студента при редактировании;
- обновление существующей записи.

### `js/details.js`

Отвечает за загрузку и отображение подробной информации о выбранном студенте.

## IndexedDB

Для хранения данных используется браузерная база данных IndexedDB.

Название базы данных:

```text
studentManagementDB
```

Версия базы данных:

```text
1
```

Название object store:

```text
students
```

Работа с IndexedDB выполняется асинхронно.

Для удобства стандартные события IndexedDB оборачиваются в `Promise`, благодаря чему в остальных частях приложения можно использовать:

```js
async
```

и:

```js
await
```

Например:

```js
const students = await getAllStudents();
```

В этом случае выполнение функции ожидает получения данных из IndexedDB, после чего приложение может отобразить студентов в таблице.

## Удаление студентов

Перед удалением записи приложение запрашивает подтверждение пользователя с помощью:

```js
confirm()
```

Это предотвращает случайное удаление студента.

После подтверждения соответствующая запись удаляется из IndexedDB, а таблица студентов обновляется.


## Асинхронная работа

IndexedDB работает асинхронно, поэтому функции взаимодействия с базой данных используют `Promise`.

В коде интерфейса применяются `async` и `await`.

Например:

```js
async function loadStudents() {
    try {
        const students = await getAllStudents();

        // Отображение студентов
    } catch (error) {
        console.error(error);
    }
}
```

`await` позволяет дождаться завершения операции IndexedDB перед использованием полученных данных.

`try...catch` используется для обработки возможных ошибок при выполнении асинхронных операций.

## Запуск проекта

Проект не требует установки дополнительных библиотек, npm-пакетов или фреймворков.

Для запуска необходимо:

1. открыть проект в WebStorm или другом редакторе;
2. запустить `index.html` через локальный веб-сервер;
3. открыть приложение в браузере.

Использование локального сервера рекомендуется из-за особенностей работы браузерных API и origin.

Данные IndexedDB хранятся локально в браузере и привязаны к текущему origin.

Это означает, что данные, созданные, например, для:

```text
http://localhost:63342
```

не будут автоматически доступны приложению, запущенному с другого origin.
